# 发布标题与正文

发布页上的标题与正文都由脚本生成。要改文字，只改 `.github/scripts/generate-release-notes.mjs`，工作流里只有文件路径。

## 1. 标题怎样拼成

标题只有一个来源，就是标签。前缀是脚本里的常量，标签通过形状校验之后直接接在后面。

```text
git tag v1.0.0
   │
   │ 发布工作流手动触发，tag 输入同一个标签
   ▼
TAG_PATTERN  ^v\d+\.\d+\.\d+$
   │
   ├── 不匹配 ──▶ 退出，不发布
   │
   ▼ 匹配
version = 标签
   │
   ▼
title = "VerseBox A9 " + version
   │
   ▼
release-title.txt ──▶ 发布动作的 name 字段
```

拼出来的三段各是什么，看这张表。

| 段 | 值 | 来源 |
| --- | --- | --- |
| 前缀 | `VerseBox A9 ` | 脚本常量 `RELEASE_TITLE_PREFIX`，末尾带一个空格 |
| 标签 | `v1.0.0` | 发布输入的 tag |
| 结果 | `VerseBox A9 v1.0.0` | `release-title.txt` 里的一行 |

标题里不加日期。日期不属于版本，也不属于产物，加进去等于把发布时刻钉在标题上，同一个标签换个日子重发就会改名。想查发布时刻，索引里的写入时刻与发布页的时间线都记着。

判据是读 `release-title.txt`，只有一行，内容等于前缀加标签。

## 2. 正文从哪来

正文没有手写部分，四样事实拼出来。

```text
上一个标签 + 当前标签
   │
   ▼
git log <区间>                    ──▶ 提交标题列表
   │
   ▼
提交标题 + 打包报告 + 附件清单
   │
   ▼
CHANGELOG.md
   │
   ▼
发布动作的 body_path
```

脚本读三类事实：提交历史里的标题、打包报告里的载荷哈希与文件数、附件清单里的哈希与字节数。它不读任何手写文本，所以同一个标签重跑两次，正文逐字相同，发布因此可以复核。

## 3. 正文有哪几节

| 小节 | 内容 | 来源 |
| --- | --- | --- |
| 本次发布 | 发布版本、标签、ROM 版本、ROM id、客体、Android 版本、载荷哈希与字节数、载荷文件数、构建提交、构建记录 | tag、打包报告、配置文件 |
| 更新 | 区间内的每条提交，写成标题加八位短哈希的链接 | 提交历史 |
| 产物 | 每个附件的相对路径、字节数、哈希 | 附件清单 |
| 校验 | 一行下载后使用的校验命令 | 模板 |
| 结尾 | 与上一个标签的完整变更链接 | 模板，首个标签时省略 |

产物一节列出的是附件清单里的全部文件，含校验清单本身。索引里不记校验清单，因为它描述的是别的文件，这一点见[03-RELEASE-INDEX](03-RELEASE-INDEX.md)。

## 4. 区间怎样确定

上一个标签用 git 的描述命令取，取的是当前标签的父提交上最近的一个标签。这个做法与标签怎样命名无关。

不按版本号大小排序，因为补发旧版本时版本号会往回走，而标签在提交历史里的先后才是真正的发布顺序。

判据是脚本打印的区间那一行，它同时给出两个端点与提交条数。

## 5. 三种边界

| 情况 | 行为 | 为什么 |
| --- | --- | --- |
| 仓库里只有这一个 tag | 正文写一句说明没有可比较的上一个版本，不给完整变更链接 | 首发的历史是整个仓库，逐条列没有信息量，而构建不该因此变红 |
| 两个 tag 之间没有提交 | 正文写一句说明这个标签范围内没有新增提交 | 空列表在页面上是一片空白，读者无法判断是漏了还是真的没有 |
| 检出是浅克隆 | 脚本直接失败 | 半份正文比没有正文更坏，读者会以为那就是全部 |

提交标题里的反斜杠、反引号、星号、下划线、方括号与尖括号会被转义。GitHub 的 Markdown 会把这些字符当成格式，一个带星号的标题会让后面整段变成斜体。

## 6. 判据

在仓库根运行正文脚本，参数依次是标签、仓库名、附件清单、配置文件、打包报告、提交号、构建记录地址与三个输出文件。

```bash
node .github/scripts/generate-release-notes.mjs \
  --tag <标签> --repo <owner/repo> --assets release-assets.json \
  --rom-properties rom/rom.properties.yaml --pack-report <打包报告> \
  --commit <提交> --run-url <运行地址> \
  --notes CHANGELOG.md --title release-title.txt --version-out release-version.txt
```

正常输出三行，分别是版本、标题与区间。任何一行不对就停下，不要拿去发布。
